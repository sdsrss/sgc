# v2.0.2：按安装 scope 给出正确的重装建议，补上测试和 CI 的缺口
状态：进行中

## 背景与目标
2026-11-02，用户把 v2.0.1 报告的遗留项交给我："你深入思考，给出科学准确的建议，然后按你的建议执行"。

事实（本会话实测，Claude Code 2.1.316，隔离 HOME）：
- project scope 安装、缓存里的 bin/sgc.mjs 被删除时：
  - 现在的建议第一步 `claude plugin uninstall sgc@sgc`（默认 user scope）→ `✘ … is enabled at project scope`；
  - `claude plugin update sgc@sgc` → "already at the latest version (2.0.1)"，文件没回来；
  - `uninstall --scope project` 再 `install --scope project` → 文件恢复（1,950,051 字节，755）。
- local scope：默认 scope 的 uninstall → `installed in local scope, not user. Use --scope local`；`--scope local` 的 uninstall + install → 文件恢复。
- 本地目录 marketplace：`claude plugin list` 显示 `Read from: <源目录>/plugins/sgc`，插件直接从源目录读，重装不起作用。
- `--plugin-dir`：插件列在 "Session-only plugins"，显示 `Path: <目录>`；只在带同一个 `--plugin-dir` 的 `claude` 里列出。
- `npm root -g`（npm 11.19.0）：前缀中任何 UUID 形状的一段都输出为 `***`，`--json` 也一样（`@npmcli/redact` 的 UUID 规则）。
- plugin-content.test.ts 用 `-t` 只选别的测试时，临时目录从 1 个变成 2 个（describe 收集阶段就 mkdtemp，afterAll 不执行）。

## 决策与进展
- 级别：L2。not-found 建议是 v2.0.1 CHANGELOG 写明要做到的行为（"advice that restores the plugin's files"），对 project/local scope 不成立，属于恢复已文档化行为的修复；跨 25 个插件文件和测试，所以写 spec。
- 不改 npm UUID 打码：nvm、Homebrew、volta、系统包等常见安装方式的全局前缀里都没有 UUID；要绕开只能自己重新实现 npm 的 prefix 解析（npmrc、环境变量、默认值）。现在的结果是这一步跳过、报错信息里给出 `npm i -D playwright` 的替代办法，不会出错。
- 不改 Windows npm.cmd：README、package.json、CI 都没有声明支持 Windows，本机也没法验证，改了也拿不出证据。
- 不做检查 P 的历史说明句：这个检查只在有 src/sgc.ts 的源码仓库里运行（`hasSource`），用户的 doctor 会跳过；误报时会直接报 fail，那时就有可复现的输入了。
- bash 3.2 用 macOS runner，不在 Linux 上编译：测的就是用户实际用的那个 shell（Apple 的 3.2.57 和 /bin/zsh），不用维护编译步骤；仓库是公开的，不额外收费。

- 意外：第一次跑完整套件时我直接用了 `bun test`，没设 `SGC_FORCE_INLINE=1`，而本机环境里有 OPENROUTER_API_KEY，于是触发了真实、计费的 LLM 调用（一次完整、一次中途停掉）。花费分不出来：这个 key 当天用量 $8.43 里还包含别的用途；按每次完整 eval $0.68–0.77 估算，约 $0.7–1.5。之后所有运行都设了 `SGC_FORCE_INLINE=1` 并去掉了 key；runbook 记忆已补上这条。
- 提交拆分：临时目录的修复和 not-found 执行测试写在同一处代码里，验证过的只有两者合在一起的状态，所以放在同一个提交里。
