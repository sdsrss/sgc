事实（本会话实测）：
- **插件加载失败**：`plugins/sgc/hooks/hooks.json` 的 `"hooks"` 是数组，形如 `[{matcher:"SessionStart", hooks:[…]}]`。Claude Code 文档要求的是"事件 → 列表"的对象。
  - Claude Code 2.1.316 下 `claude plugin validate plugins/sgc` → exit 1（HOOKS_SCHEMA_INVALID）。
  - 在隔离 HOME 里从本地仓库安装 → `Status: ✘ failed to load`，命令、技能、agent 全都不可用。
  - 该文件自 6475f6b（2026-05-19）起没改过，v1.38.5 也一样。
  - README:171 写明插件包含 "SessionStart hook"；6475f6b 的提交说明写明 "auto-inject current-task on SessionStart"。
- **注入的内容已过时**：这个 hook 会 `cat` `skills/bootstrap/SKILL.md`（3,986 字节），其中写着 "`bun ≥1.3` is required as the runtime in **both** modes"，还有 `npm install -g @sdsrs/sgc  # requires bun >=1.3 as the runtime`。实际上从 v1.24 起运行时就是 Node，插件命令也优先用自带的 `bin/sgc.mjs`（17 个命令文件都如此）。
- **退回 1.x 的插件路线也坏了**：v2.0.0 的旧 Node 提示和 CHANGELOG 让插件用户退回 `sdsrss/sgc#v1.38.5`，但 v1.38.5 的插件同样加载失败。
- **researcher.history**：v2.0.0 的测量日志里，默认模型 opus-4.7 的 5 次失败（smoke 4 次 + full 1 次）全是运行时错误 `OutputShapeMismatch: agent researcher.history output missing required fields: warnings`，不是评测门。
  - 原因：manifest 要求 `warnings: array[string]`，而 prompt 的回复格式写的是 `warnings:\n  - <optional string per warning>`，模型在没有警告时会把整个键省略。spawn 在 coerce 之前先校验，于是判为致命错误。`sgc plan` 会把它退化成空的 prior_art，即这次的历史方案检索被悄悄丢掉。
  - **更正**：v2.0.0 的 CHANGELOG 和 `v2-node22-floor.md` 说"失败多数是 30 词上限和引用匹配，不是运行时错误"，这对默认模型不成立。30 词上限的失败只出现在 opus-5.5（3 次）和 sonnet-5.5（10 次）上。
  - 其余 22 个带 prompt 的 agent 里，没有别的 manifest 必填字段被 prompt 写成"可选"（`bun -e` 扫描）。

## 方案
- hooks.json：`{"hooks":{"SessionStart":[{"hooks":[{"type":"command","command":"…"}]}]}}`。
  - 不写 matcher，即 startup / resume / clear / compact 都触发。
  - 去掉 `"async": false`（默认就是 false）。
  - 新增测试，按文档结构校验：顶层 `hooks` 是对象，每个事件对应一个数组，每个元素都有 `hooks` 数组。
- 注入内容：见「待用户决定」A-i。
- prompt：回复格式改为 `warnings: []`，并加一句：两个顶层键都必须给出，没有警告时写 `warnings: []`。
- 实测：e1–e3 在默认模型上跑 N=10 轮（每轮约 3 次调用），预计 ≤ $0.5，上限 $1。
